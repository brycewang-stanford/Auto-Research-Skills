\begin{abstract}
We describe Free-Research-Crew, an open set of research-assistant (RA) agents that take a
research question to a compiled paper in computer science or empirical social science,
including the experiments or data analysis behind it. The agents run inside existing
coding-agent command-line tools (Claude Code, Codex) and hand work to each other only
through files in a shared workspace. A small, dependency-free tool enforces the
workspace protocol: analysis cannot run before a human approves the study design, every
number in the paper is generated from a logged run whose code has not changed since,
every reference carries a record of how it was checked against its source, and
submission requires a clean re-execution that reproduces every metric. One agent, the
Reviewer, does nothing but attack the others' work; it reads the files rather than the
authors' account of them, can run on a different provider's model, and blocks each of
four human-approved gates while it has an open critical finding. We release the crew,
the protocol and a bench of seed tasks with hidden answer keys, including a dataset on
which the true effect is exactly zero. On seven seed tasks the crew produced seven papers
that passed all four gates and a clean rerun; the Reviewer raised 14 critical, 271 major
and 480 minor findings across 83 review rounds, and no gate was approved over an open
critical finding. On the null-effect seed the crew did not report an effect.
\end{abstract}

\section{Introduction}

Agents that write research papers end to end now exist in many forms
(Section~\ref{sec:related}). Their outputs are hard to trust for a simple reason: the
same system that produces a result also decides that the result is good. It chooses
the specification after seeing the data, types the numbers into the paper, recalls the
references, and grades its own draft. Each of these steps is a place where an error or
a convenient choice can enter without anyone noticing.

Free-Research-Crew is built around separating those judgments. We distinguish three:
\begin{enumerate}[nosep]
  \item \emph{what happened} (did the run finish; does the number in the paper equal the
        logged metric) --- decided by a deterministic tool;
  \item \emph{whether it is good} (does the design identify the effect; does the evidence
        support the claim) --- decided by a Reviewer agent that did not do the work;
  \item \emph{whether to go on} --- decided by a human at four gates.
\end{enumerate}
The design borrows directly from ARIS \citep{aris}, whose central rule is that a loop
may drive itself toward a goal but may not acquit itself.

Our contributions are: (i) a file-based protocol for multi-agent research with
mechanically enforced provenance (Section~\ref{sec:protocol}); (ii) a crew of nine roles
covering two tracks, empirical machine learning and empirical social science, with an
adversarial Reviewer (Section~\ref{sec:crew}); (iii) a bench of seed tasks with hidden
answer keys, including a replication of a published double machine learning estimate
and a null-effect dataset (Section~\ref{sec:bench}); and (iv) a gallery of complete
workspaces, failures included (Section~\ref{sec:results}).

\section{Protocol}\label{sec:protocol}

A crew workspace is a directory of plain files: the plan (question, hypotheses, design,
task board, gates), the bibliography with a verification record per entry, a data
manifest with hashes, the run ledger, a list of claims, the paper, and the reviews.
Agents never pass results to each other in conversation.

\paragraph{Gates.} Four gates --- question, design, results, submission --- are passed in
order, each approved by a named human. Approving a gate re-validates the whole
workspace; an approval that would leave it invalid is rolled back.

\paragraph{Pre-specification.} The tool refuses to execute an \emph{analysis} run until
the design gate is approved. Data preparation runs are allowed earlier. This makes the
analysis plan binding in the way a pre-analysis plan is meant to be.

\paragraph{The run ledger.} Every run is executed by the tool, which records the
command, timestamps, exit code, the SHA-256 of every code, input and output file, and
the metrics the command writes. If a code file changes after its run, the workspace
fails validation until the run is repeated.

\paragraph{Claims and numbers.} Every result the paper states is a claim linked to a
successful analysis run and a named metric; its value must equal that metric. Claims
with a macro name are rendered into a generated \LaTeX{} file, and the writer agent
cites \verb|\AteMain| rather than typing a number. Citation claims must point to a
bibliography entry with a verification record (how it was checked, by whom, when).

\paragraph{Clean rerun.} Before submission the workspace is copied, every recorded
output is deleted, every run is re-executed in order, and each metric is compared with
the ledger. Submission requires a passing report newer than every run.

\section{The crew}\label{sec:crew}

The PI agent runs in the main session, plans, delegates and brings decisions to the
human. Eight further roles run as sub-agents: Scout (literature and source
verification), Designer (fixes the design before outcomes are seen), Data RA
(acquisition and provenance), Econometrician or Experimenter (the analysis, by track),
Figures RA, Writer, Replicator, and Reviewer. Each role has a written contract: what it
reads, what it may write, when it is done, and what it never does.

\paragraph{The Reviewer.} Following ARIS, the Reviewer (i) is briefed only with the
workspace path, the stage and the round --- never a summary or the authors' opinion;
(ii) opens every review with a single \emph{kill argument}, the strongest case for
rejection in under 200 words; (iii) lists findings tied to a file and a place, with a
severity; (iv) keeps its own memory across rounds and rules on the authors' rebuttals;
and (v) stops after four rounds, leaving open findings to the human. A gate cannot be
approved while the latest review of its stage has an open critical finding, unless the
human overrules it on the record, which is disclosed in the paper. The Reviewer can run
on a different provider's model than the authors (cross-family review).

\section{Bench}\label{sec:bench}

Each seed task is a question, a brief, requirements and a compute budget (a laptop CPU
and under an hour). Where there is a right answer, a hidden key states it and a scorer
checks it mechanically. The seeds run so far are:
\begin{itemize}[nosep]
  \item \textbf{ss-dml-401k}: replicate the partially linear double machine learning
        estimates of the effect of 401(k) eligibility on net financial assets
        \citep{chernozhukov2018}, scored against the published table;
  \item \textbf{ss-null-effect}: evaluate a voluntary job-training program from
        synthetic administrative data in which the program has no effect, selection
        is on observables, and many outcomes and survey items invite specification
        search; the crew passes only if it does not find an effect;
  \item \textbf{cs-label-noise}: a controlled study of how symmetric training-label
        noise affects gradient boosting, random forests and logistic regression;
  \item \textbf{ss-card-krueger}: replicate the difference-in-differences estimates of
        the New Jersey minimum-wage increase \citep{card1994minimum} from the public
        data, scored against the published tables;
  \item \textbf{ss-lalonde-observational}: ask whether observational estimators on the
        NSW treated men and a CPS comparison group recover the experimental benchmark
        \citep{lalonde1986,dehejia1999};
  \item \textbf{cs-calibration}: test published claims about the calibration of common
        tabular classifiers and post-hoc recalibration \citep{niculescumizil2005}.
\end{itemize}
A regression-discontinuity replication of the US Senate incumbency advantage
(\textbf{ss-rd-senate}) was run as a low-cost trial; an instrumental-variables
replication of the return to schooling has an answer key but has not yet been run.

\paragraph{Outcomes.} On the null-effect seed the crew reported an effect of $-\$9.8$
(95\% CI $[-358, 338]$) and did not report a secondary outcome with an uncorrected
$p = 0.044$; the answer key scores this a pass. The 401(k) replication put all ten
cells of the published table inside tolerances fixed before the analysis, but its paper
says plainly that the test cannot see shifts of a few hundred dollars and that the lasso
cell could not be tested. The Card--Krueger replication reproduced two of three
pre-stated targets; the third (the difference in means in the published Table~3) is
within tolerance but not at published precision, and the paper says the source of the
gap is unidentified. The label-noise study ended with both hypotheses inconclusive. The calibration study
contradicted its first hypothesis (random forests did not have the lower plug-in
calibration error on two of four datasets, because logistic regression was
miscalibrated there), and its two recalibration hypotheses ended inconclusive and ``no
difference'', both depending on a single dataset. On the LaLonde comparison the
pre-specified estimator gave a contrast of \$1,573 (95\% CI $[9.6, 3{,}136]$) between
the NSW treated men and CPS men; the first hypothesis held by its rule, but three of
five cross-fitting repetitions on their own did not exclude zero, the placebo test on
1975 earnings failed, and three pre-specified checks moved the interval across zero, so
the paper reports a statistical contrast rather than an effect of the program and lists
the reporting changes made after the results were seen. No gate was approved over an
open critical finding.

\paragraph{A low-cost run.} The seventh paper (\texttt{ss-rd-senate}, a
regression-discontinuity replication) ran every role subagent, the Reviewer included, on
Claude Haiku 5.5, with the PI on Claude Opus 5.5. It reproduced the printed output under
an unverified software setting, passed its answer key and its clean rerun, and cost about
\$16 in model usage, of which about \$2 was the 23 subagent runs; the PI session became
most of the cost. The Haiku Reviewer still blocked the first question, overruled the PI
twice and caught a reversed sign and a unit-scale error, but needed 15 rounds; the clean
rerun exposed two bugs in the workspace tool, which were fixed with tests.

\paragraph{What the Reviewer caught before any data were analysed.} In the first round
on the label-noise seed, the Reviewer found that the main hypothesis averaged accuracy
losses over datasets that had not been named and whose number of classes made a given
noise rate mean different things; the hypothesis was rewritten to be decided per
dataset with an explicit rule. On the 401(k) seed, it found that the proposed
replication tolerance was sized to sampling error rather than to the split-to-split
variation that a re-run on the same data can produce, which made the test nearly
powerless; the tolerance was rederived from the published table.

\paragraph{A protocol breach.} In the same first round, the Reviewer ran a small pilot
of the three classifiers on three toy datasets to support its argument, before the
design gate. The pilot informed the revised question. We disclosed it in the plan,
excluded those datasets from the study, and added an explicit rule to the Reviewer's
contract. The tool cannot prevent an agent from running code outside the ledger; this is
the protocol's main remaining gap.

\section{Related work}\label{sec:related}

\paragraph{End-to-end AI-scientist systems.} The AI Scientist \citep{lu2024aiscientist}
generates ideas, runs experiments from code templates, writes the paper and runs a
simulated review of it; its successor \citep{yamada2025aiscientistv2} replaces the
templates with agentic tree search and reports one fully generated paper that scored
above the average acceptance threshold of an ICLR workshop. The Agentic Scientist
\citep{lange2026agentic} rebuilds the pipeline as orchestration over coding agents, with
rubric verification at each stage. Agent Laboratory \citep{schmidgall2025agentlab} takes
a human-provided idea through literature review, experimentation and report writing,
and finds that human feedback at each stage improves the result; AI-Researcher
\citep{tang2025airesearcher} automates the path from literature to manuscript and
proposes its own benchmark. Co-Scientist \citep{gottweis2026coscientist} targets
hypothesis generation rather than papers. Closest to our aims is data-to-paper
\citep{ifargan2025datatopaper}, which traces each result programmatically back to code
and data so that the paper can be verified. Independent evaluations are more sobering:
an evaluation of the first AI Scientist reports failed experiments, misleading results and
hallucinated numbers \citep{beel2025sakana}, and a controlled study of two open-source
systems finds that inappropriate benchmarks, data leakage, metric misuse and post hoc
selection are largely invisible in the final manuscript, and recommends auditing the
workflow artifacts instead \citep{luo2026pitfalls}. The crew follows that recommendation;
it is not a more capable scientist. Where these systems let one pipeline both produce and
judge its results, the crew gives judgments of fact to a deterministic tool and
judgments of quality to a separate Reviewer, and makes the ledger, hashes and
verification records the object of review. To our knowledge, none of them refuses to
execute analysis code until a human has approved the design.

\paragraph{Deep-research and literature agents.} Systems such as STORM
\citep{shao2024storm} and PaperQA \citep{lala2023paperqa} retrieve and synthesise
literature into cited text. The crew does not compete on retrieval; its Scout records,
for each bibliography entry, how the entry was checked against its source, and the tool
rejects citation claims that lack such a record.

\paragraph{Skill libraries and ARIS.} Skills, folders of instructions and scripts that a
coding agent loads when needed \citep{agentskills}, have become a common
way to package research workflows, from domain libraries \citep{kdense2025skills} to a
vendor workbench whose reviewer agent checks citations and calculations
\citep{anthropic2026claudescience}. ARIS \citep{aris,yang2026aris} is the nearest
relative: Markdown skills run inside a coding agent, an executor model is critiqued by a
reviewer from a different model family, and a claim audit cross-checks manuscript
statements against a claim ledger and the raw evidence. The crew takes its Reviewer from
ARIS. It differs in two ways. It moves assurance from instructions into a tool that
refuses to act: no analysis run before the design gate, no gate approval without the
human's input, no number that is not tied to a run whose code hashes still match, and no
submission without a clean rerun. And it divides the work among roles that communicate
only through files.

\paragraph{Benchmarks.} MLAgentBench \citep{huang2024mlagentbench} scores agents on
machine-learning experimentation, ScienceAgentBench \citep{chen2025scienceagentbench} on
data-driven tasks drawn from published papers, DiscoveryBench
\citep{majumder2025discoverybench} on hypothesis search over given datasets, and
CORE-Bench \citep{siegel2024corebench} on reproducing published computational results.
Project-level benchmarks find end-to-end autonomy weak: current agents remain far from
re-discovering published results \citep{xu2026researchclawbench}, and average scores on
ASI-Bench fall from 50.9 to 26.6 as methodological guidance is withdrawn
\citep{zhou2026asibench}. We have not evaluated the crew on any of them. Our seed bench
asks a different question, whether the process holds when the honest answer is
uninteresting; seven papers are a demonstration, not a measurement of capability.

\paragraph{Pre-registration and specification search.} The gates encode a lesson from
psychology and economics. Undisclosed flexibility in collecting, analysing and reporting
data makes false positives far more likely than the nominal rate \citep{simmons2011}.
Tests published in leading economics journals show missing p-values between 0.10 and
0.25 and a matching excess just below 0.05 \citep{brodeur2016}, and the excess varies by identification
method, with instrumental variables and difference-in-differences the most affected
\citep{brodeur2020}. Analysts given the same data and question make different choices and
reach different answers \citep{silberzahn2018,huntingtonklein2021}, and large replication
projects reproduced many fewer significant effects than were originally reported
\citep{osc2015,camerer2016}. The responses include pre-analysis plans and pre-registration
\citep{olken2015,nosek2018}, specification-curve analysis \citep{simonsohn2020}, and
broader transparency and data-sharing norms \citep{christensen2018}. For an agent,
specification search is fast and nearly free, so the crew enforces pre-specification
mechanically rather than by disclosure, and the null-effect seed tests it directly.

\paragraph{Language models as reviewers.} Comments that GPT-4 wrote on papers overlapped
with those of human reviewers about as much as two human reviewers overlapped with each
other \citep{liang2024feedback}. But models rate text they recognise as their own more
favourably \citep{panickssery2024}, and without external feedback they do not reliably
correct their own reasoning \citep{huang2024selfcorrect}. These findings motivate a
Reviewer that did not do the work, reads files rather than summaries, and can run on
another provider's model. We have not measured how much cross-family review adds.

\section{Limitations}

Human approval of gates is enforced by a hook that refuses an approval unless the
human's latest input approved that gate, but an agent determined to evade it could
still write and run a script; the hook narrows the path, it is not a sandbox. The tool
checks that numbers trace to runs, not that a source says what a claim attributes to it;
that is the Reviewer's job, and a reviewer can be wrong. Same-family review shares the
authors' blind spots. Seeds are small by design. The gallery papers are demonstrations
and are not submitted to venues.
