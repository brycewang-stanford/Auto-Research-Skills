\section*{AI-use statement}

This paper was drafted by a crew of AI research-assistant agents
(Free-Research-Crew, protocol v0.1) under the direction of the human author, Bryce Wang.
He approved the research question, the design and the results at three human gates, and
the manuscript itself is subject to a fourth, the submission gate. He takes responsibility
for the paper's content.

\begin{itemize}
  \item \textbf{Roles and models.} Every crew role ran on Anthropic Claude through Claude
        Code. The PI role was the main Claude Code session. The Scout, Designer, Data RA,
        Econometrician, Figures RA, Reviewer, Writer and Replicator ran as subagents
        launched from that session. The review records name the model as
        \texttt{claude-opus-5-5}. The Replicator's clean rerun is reported below.
  \item \textbf{The PI session held the answer key.} The same session that acted as PI
        wrote the synthetic dataset's generator and its hidden answer key, so it knew the
        true effect. It also drafted the research question and hypotheses, replaced the
        \$1,000 equivalence margin with 10\% of enrolees' mean 1975 earnings at the
        Reviewer's suggestion, wrote the pre-gate diagnostics into the plan, issued the
        pre-gate rulings that let two runs read the outcome columns, and wrote every brief
        to the other agents. Briefs were archived (\texttt{briefs/}) only from the
        Writer's revision brief after the first paper review on (2026-11-18, 15:11 UTC).
        All earlier briefs were not archived, including the Figures RA's brief, the
        Writer's drafting brief and the brief for the first paper review;
        \texttt{briefs/RECONSTRUCTION.md} is the PI's after-the-fact reconstruction and
        cannot be verified. The agents that analysed the data and wrote the paper did not
        open the answer key; that the key did not reach them through the briefs rests on
        the PI's word.
  \item \textbf{Review.} The Reviewer agent ran 3 rounds on the research question, 3 on the
        design, 1 on the code, 2 on the results and 2 on the paper (the second passed with two
        minor findings, which this version answers). No literature
        review round was held, although the crew's playbook calls for one before the design
        gate. Its independence level was \emph{fresh-context}: a new context in every
        round, with the same model family as the other roles. The human author chose this
        over a cross-family reviewer. The code review took place after the analysis runs,
        because the study's plan predates the crew's rule that code is reviewed before any
        analysis run (see Section~\ref{sec:deviations}); it passed with four minor findings.
        These were answered in the files and judged answered in the second results round,
        but they are still marked open in the code-review record. The final question round
        and the final results round each passed with two minor findings still open; the
        human approved those gates, and the open findings were then addressed (by the
        design, and by the figures and the approximation wording, respectively).
  \item \textbf{Findings accepted over the Reviewer's objection.} None.
  \item \textbf{Retroactive ruling.} The PI's ruling on design-review finding F4, which
        allowed a pre-gate run to count missing outcome values by arm, was logged only
        after that run, at the Reviewer's request, and is marked as retroactive. That it was
        given before the run rests on the PI's word (Section~\ref{sec:deviations}).
  \item \textbf{Log repair.} The PI chose to remove a hand-written Scout entry with a
        future timestamp from the append-only log, and logged the removal. The Reviewer
        (question round 1, finding F8) had asked only that the entry be corrected or
        explained.
  \item \textbf{Evidence.} Every number in the text is a macro generated from the metrics
        of a logged run. Every table cell is either such a macro or written by a logged
        table script from run metrics; no result number was typed by hand. The numbers typed
        by hand are of three kinds: design facts fixed in the plan (including the pre-gate
        precision proxies and the margin's earlier \$1,000 value); dates; and process facts
        about the review and the replication (the review-round counts, the citation counts
        below, the run counts and the rerun's 183 seconds), taken from \texttt{reviews/},
        \texttt{sources/sources.json}, \texttt{replication.json} and
        \texttt{REPLICATION.md}. Every citation was checked against its source by the Scout: 9
        from the full text and 14 from the abstract or opening text only. Where only the
        abstract or opening text could be read (as for \citet{imbens2003} and
        \citet{hirano2003}), the paper cites the source for no more than that text says.
        The full workspace is public at
        \url{https://github.com/brycewang-stanford/Free-Research-Crew/tree/main/gallery/ss-null-effect}.
        It contains the plan, the run ledger, the code, the data manifest, every review,
        the archived briefs, the PI's reconstruction of the earlier ones, the replication
        record and this paper's sources.
  \item \textbf{Replication.} The Replicator's clean rerun passed: \texttt{replication.json}
        (created 2026-11-19T01:26:40Z) records all 23 logged runs reproduced at the
        protocol tolerance (relative $10^{-6}$, absolute $10^{-9}$). As facts about that
        replication: the environment was built fresh from \texttt{code/requirements.txt}
        alone; the data were re-copied from the seed and re-verified by hash, not reused;
        the thread count was set to one (\texttt{OMP\_NUM\_THREADS=1}) because the machine
        was shared; and the rerun took 183 seconds. No code, data or tolerance was changed
        for it. An earlier clean rerun, on 2026-11-18, failed: it reproduced 10 of 23 runs.
        Every run that executed matched its record; the failures were crashes, with two
        causes that were fixed before the passing rerun. (A)~The crew's rerun tool broke a
        tie between two data-preparation runs with the same start time alphabetically, so
        the margin ran before the covariate file it reads existed, and every run depending
        on it failed. The tool now runs each run after every run that produced one of its
        inputs. (B)~A diagnostic rerun with the order corrected reproduced 22 of 23 runs.
        The exception was the main table, whose script checks claimed values exactly: the
        random-forest run summed its per-tree predictions in thread-dependent order, so its
        metrics varied in the last bits. Its prediction was made single-threaded, and that
        run and the figure and table runs built on it were re-recorded; no printed number
        changed (Section~\ref{sec:deviations}). The Replicator's full account is in
        \texttt{REPLICATION.md}.
\end{itemize}
